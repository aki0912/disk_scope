# DiskScope

SwiftUIとRustで作った、macOS向けのストレージ可視化アプリです。フォルダやSSDを選択すると、容量の割合を長方形の面積で表示します。

## 起動

XcodeのSwiftツールチェーン、Rust/Cargoが必要です。外部パッケージには依存しません。ソースの対象はmacOS 14以降ですが、今回生成したアプリの動作確認はmacOS 27 / Apple Siliconで行っています。この環境のHomebrew版Rust標準ライブラリはmacOS 27向けのため、以前のmacOS用に配布する場合は、そのOSに対応したRustツールチェーンで再ビルドしてください。

```sh
./scripts/run.sh
```

ビルド済みアプリは `build/DiskScope.app` です。Finderから起動でき、必要に応じてアプリケーションフォルダへコピーできます。このビルドはローカル用のアドホック署名です。他のMacへ配布するためのDeveloper ID署名・公証は含みません。

## 使い方

1. 「フォルダを選択」または `⌘O` で解析対象を指定します。外部SSDは、そのボリュームを選択します。
2. 大きい長方形から容量の使い道を確認します。クリックすると、容量、割合、更新日などが右側に表示されます。
3. フォルダをダブルクリックするか、一覧の矢印で内部へ移動します。パンくずリストや `⌘↑` で上の階層へ戻れます。
4. 一覧で現在の階層を名前検索できます。「Finderで表示」で実ファイルの場所を開きます。
5. 解析後にファイルを変更した場合は `⌘R` で再解析します。

「ディスク上の使用量」と「ファイルサイズ」を切り替えられます。面積の基準は現在表示しているフォルダです。色は拡張子から判断したファイル種別を表し、フォルダには一段下の内容も表示します。小さい項目が多い場合、ツリーマップは「その他」にまとめます。一覧は検索条件に合う上位300件を表示します。

解析中は確認したファイル数・フォルダ数・使用量を表示し、キャンセルできます。走査前に総件数が分からないため、完了率や残り時間は推測して表示しません。削除・移動機能や外部への通信はありません。

## 容量の意味と制約

- ディスク上の使用量は `st_blocks × 512`、ファイルサイズは `st_size` に基づきます。表示単位は10進数です（1 KB = 1,000 B）。
- スパースファイルの未割り当て領域は、ディスク上の使用量に含みません。ファイルの内容は読み込みません。
- APFSクローンの共有ブロック、スナップショット、圧縮、ファイルシステムの管理領域などのため、ファイルの合計はボリュームの使用量や削除で空く容量とは一致しません。
- フォルダ自体の管理領域は集計に含めません。ハードリンクはデバイスIDとinodeで識別し、最初に見つかった1件だけに容量を計上します。並列走査のため、どのリンクに計上するかは変わることがあります。
- シンボリックリンク自体を集計しますが、リンク先は走査しません。別のファイルシステムへの境界と特殊ファイルは対象外です。内蔵SSDのルートを選んでも、別のマウント先まで自動的には解析しません。
- アクセスできない項目や解析中に消えた項目は記録し、読み取れた範囲で結果を表示します。エラーの詳細は最大100件です。必要に応じてシステム設定の「プライバシーとセキュリティ → フルディスクアクセス」でアプリを許可し、再解析してください。
- 解析はある時点のスナップショットではありません。解析中の変更によって値が変わる可能性があります。
- 最近解析したフォルダの場所を最大5件、macOSのUserDefaultsに保存します。解析結果そのものは保存しません。
- 最近の場所をクリックすると選択ダイアログが開きます。場所を確認して「解析する」を押してください。macOSのアクセス許可を引き継げない場合にも、対象フォルダを選び直せます。
- 走査結果はメモリに保持します。使用メモリは項目数に比例し、数百万件の規模ではメモリ負荷が大きくなります。

## 構成

| 場所 | 役割 |
| --- | --- |
| `rust/src/lib.rs` | 最大8ワーカーによるディレクトリ・メタデータの並列走査、集計、キャンセル、C ABI |
| `Sources/CScanner/` | SwiftからRustを呼び出すCヘッダー |
| `Sources/DiskScopeCore/` | 解析結果モデル、容量表記、ツリーマップの配置計算 |
| `Sources/DiskScope/` | SwiftUI画面、Canvas描画、バックグラウンド結果読み込み |
| `Tests/DiskScopeCoreTests/` | 面積・境界・重なり・階層データの検証 |
| `Tests/Model/` | 非同期検索の競合・キャンセル、Rustから受け取るバッファの解放の検証 |

Rustがファイルのメタデータだけを走査し、Swiftは約120 ms間隔で進捗を取得します。完了は別の待機APIで検知するため、次の進捗取得まで待ちません。完了結果のデコードと初回表示用の上位300件の選出はバックグラウンドで行い、準備済みの結果をSwiftUIのCanvasに渡します。結果のJSONはRustのバッファをコピーせずに読み込みます。項目の種類を小さな数値で保持し、読み込み時に全件配列の領域を事前確保して、解析後に残るメモリを減らしています。名前検索は入力が120 ms止まってからバックグラウンドで実行し、新しい入力やフォルダ移動で古い検索を中断します。

## 検証

```sh
./scripts/test.sh
./scripts/build.sh
```

Rust側ではハードリンク、スパースファイル、循環シンボリックリンク、空フォルダ、キャンセル、C ABIのライフサイクルを検証します。Swift側ではツリーマップの面積比・重なり・境界、階層復元、容量表記を検証します。最後にPython 3の標準ライブラリで13,304件のテストファイルを作成し、C ABIを通した結果と実際のメタデータを照合します。非同期検索の連続入力・容量基準変更・フォルダ移動・再スキャン、JSONデコード成功時と失敗時のバッファ解放も検証します。テストデータは終了時に削除されます。

描画の回帰検証は、macOSのGUIセッションで次を実行します。

```sh
python3 scripts/verify_treemap_rendering.py
```

小さな検証ウィンドウを表示し、マウス入力を無効にした状態で、初回スキャン、容量基準の切り替え、選択、フォルダ移動、リサイズ、同じ件数での再スキャンがCanvasに反映されることを確認します。連続キャンセル後の別フォルダへの切り替え、遅れて届いた結果の破棄、失敗時の待機終了も検証します。本番ソースの一時コピーに描画を記録する処理だけを挿入して実行し、描画を強制するAPIは使いません。テスト用ファイルは終了時に削除します。

開発時は `build/DiskScope.app/Contents/MacOS/DiskScope --scan <解析するフォルダ>` で解析対象を指定して起動できます。

## 性能の測定

大きいフォルダは512件単位でメタデータ取得を並列化し、画面に表示する上位項目だけを選出します。スキャン開始から初回の地図表示までの時間も測定しています。改善前後の実測値、測定条件、再測定の手順は [性能測定](docs/PERFORMANCE.md) を参照してください。
